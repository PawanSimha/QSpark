Features

What does QSpark offer?

QSpark is a production-grade smart parking management system that digitizes the entire parking lifecycle — from booking and real-time tracking to QR-based vehicle identification and audit trails. Below are the core capabilities.

What features does QSpark offer for parking management?

QSpark provides a complete digital parking operations platform. Administrators can book slots across 480 bays, scan QR codes for instant vehicle identification, track active and historical parking records, and export data. Every action is secured with Spring Security, BCrypt hashing, and CSRF protection.

480-Slot Dashboard

Manage 4 basements with 120 slots each. Real-time color-coded grid shows occupied vs. free slots instantly. Quick-jump navigation for fast slot selection.

QR Code Vehicle ID

Generate QR codes via ZXing for any vehicle registration. Scan with your camera to auto-fill the dashboard booking form — no manual data entry for repeat visitors.

Spring Security + BCrypt

Enterprise-grade authentication with BCrypt password hashing, form-based login, CSRF protection on every form and AJAX call, and secure headers (XSS, frame-deny, nosniff).

Full Audit Trail

Every booking records entry and exit timestamps. History tab preserves all completed parking sessions with search, sort, pagination, and CSV export.

Dual Database Support

MySQL for production and H2 in-memory for development. Seamless switching via Spring profiles. No MySQL installation needed to start developing.

Client-Side Analytics

Built-in search, multi-column sorting, client-side pagination, and one-click CSV export. Monitor active occupancy ratios in real time from the stats bar.

Architecture

System Architecture

QSpark follows a three-tier server-rendered MVC architecture. The browser receives complete HTML from Thymeleaf, which the server populates by querying the database through Spring Data JPA repositories. Spring Security guards every request at the controller boundary.

Presentation Tier

Thymeleaf templates (index.html, login.html, qrcode.html) rendered server-side. Vanilla JS for toasts, dark mode, table sorting, pagination, and QR scanning.

Application Tier

Spring Boot controllers handle auth (LoginController), CRUD (ParkingController), and QR operations (QRCodeController). Spring Security enforces auth before any controller logic runs.

Data Tier

JPA Repositories with Hibernate ORM. Three tables: admin (BCrypt passwords), parking_slot (bookings with entry/exit times), vehicle_registration (QR vehicle registry).

Vehicle Identification

How does QR scanning work in QSpark?

QSpark uses the ZXing library to generate QR codes encoding vehicle registration numbers. Administrators generate a QR PNG from the QR Code Management page, which registers the vehicle in the database. On re-entry, staff use the camera-based scanner (powered by html5-qrcode) to scan the printed QR. The decoded vehicle number is looked up in the vehicle_registration table, and if found, the dashboard booking form is auto-filled with owner name, vehicle type, and mobile number — no typing required.

QR scan flow: Scan → lookup registration → redirect to dashboard with pre-filled form → select slot → confirm booking.

FAQ

Frequently asked questions

What is QSpark?

QSpark is an open-source, production-grade smart parking management system built with Java 17 and Spring Boot 3.3.1. It manages 480 parking slots across 4 basements, provides QR-code-based vehicle identification, and includes full audit history with entry/exit timestamps. It is licensed under GNU GPLv3.

How do I install and run QSpark?

Clone the repository, ensure Java 17 is installed, and run ./mvnw spring-boot:run "-Dspring-boot.run.profiles=h2" for the H2 development profile (no MySQL required). For MySQL, set the DB_PASSWORD environment variable and run without the H2 profile. The application starts on port 8081. Default login: QSparker / QSpark@Secure.

How does QR code vehicle identification work?

Administrators generate QR codes from the QR Code Management page. The QR encodes the vehicle registration number. On re-entry, staff scan the QR using a device camera (via the html5-qrcode library). The system looks up the vehicle in the registration database and auto-fills the booking form with owner details — eliminating manual data entry.

What security measures does QSpark implement?

QSpark uses Spring Security 6.0 with BCrypt password hashing (60-character column), form-based authentication, CSRF protection on every POST form and AJAX call, session invalidation on logout, and secure HTTP headers (X-XSS-Protection, X-Content-Type-Options: nosniff, X-Frame-Options: DENY, Referrer-Policy: same-origin). API endpoints return 401 instead of 302 to prevent login page leakage.

Can I contribute to QSpark?

Yes. QSpark is free software under GNU GPLv3. Fork the repository at github.com/PawanSimha/QSpark, create a feature branch, and submit a pull request. All 63 tests must pass before merging.

What database options are available?

QSpark supports two database profiles: MySQL 8.0 for production deployments and H2 in-memory for local development and testing. The H2 profile requires zero configuration — the database is created automatically with schema auto-generation. Seed data (admin user) is handled by DataInitializer with BCrypt-encoded password.

Does QSpark require an internet connection?

No. QSpark is a self-hosted web application. Once deployed on a local server, it operates entirely on the local network. The only external dependency is the html5-qrcode library loaded from CDN for camera scanning — which can be vendored for air-gapped deployments.

What vehicle number formats are supported?

QSpark supports four Indian registration formats enforced by regex: Standard 1-letter (KA 04 A 2256), Standard 2-letter (DL 03 CA 1234), Standard 3-letter (ML 04 ASD 5256), and Bharat Series (26 BH 9876 AB). Invalid formats are rejected with user-friendly error messages.
